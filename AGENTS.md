# cams-go-utils

Read [README.md](README.md) first: it says what the package holds and who uses it. This
file holds the rules for changing it.

## Commands

```sh
go build ./...
go vet ./...
gofmt -l .              # must print nothing
go test -race ./...
go mod tidy             # and go.mod / go.sum must not change
```

`.github/workflows/ci.yml` gates on all five. Run tests with `-race` every time: the gRPC
tests serve from goroutines of their own.

## What may be imported

**No other ontavu module, and `cams-api` least of all.** This module sits below the
contract: `cams-agent` and `cams-hub` both build against it, and `cams-api` is built and
versioned on its own. A dependency from here to there would mean that every change to the
contract needs a release of this module, and back again. What belongs to the protocol (the
keepalive, the metadata keys) reaches this module as a parameter. See the README.

The check is mechanical:

```sh
go list -deps ./... | grep ontavu     # only github.com/ontavu/cams-go-utils/...
```

Nothing proprietary may come in either. `cams-hub` is proprietary, and code leaves it only
on purpose. Code that lands here takes the MPL-2.0.

The header is Exhibit A and nothing more. **Never add Exhibit B** ("Incompatible With
Secondary Licenses"): leaving it out is what keeps this module compatible with the AGPL as
a secondary licence, which is how `cams-agent` links it. Keep a blank line between the
notice and `package utils`, or Go takes the licence for the package's doc comment.

## Attribution: `Assisted-By`, never `Co-Authored-By`

A model is a tool, not an author. Work an assistant helped with ends its commit message,
and its pull request description, with one line: `Assisted-By: Claude Code`,
`Assisted-By: Codex`, and so on.

- **The tool, not the model.** Model names change every few months; the tool is what was
  actually run.
- **No address**, and no `Co-Authored-By`. Git and GitHub read that trailer as a person.
  In a copyleft project the authors are the copyright holders, and they are listed in
  `AUTHORS`.
- **Nothing in the sources.** No `// generated by` and no model name anywhere.

## Releases

Cams requires this module by its tag, never through a `replace`: its CI and its Docker
build see only the cams repository. A change therefore reaches Cams in three steps:

1. Merge it here, then tag `vX.Y.Z` and push the tag. Stay below v1 while the API moves.
2. `go get github.com/ontavu/cams-go-utils@vX.Y.Z`, then `go mod tidy`, in `cams-hub/go/`
   of ontavu/cams and in ontavu/cams-agent.
3. Make any signature change on their side in the same change as the bump.

To develop both at once, put a `go.work` in the directory that holds the clones. Commit it
to neither repository; `.gitignore` excludes it.

## Go rules

These are the rules of the Cams project (see its `AGENTS.md`), and they apply here as
written, but for the errors:

- New logic ships with its tests.
- No error is silently ignored.
- No goroutine leaks, and whoever cancels also waits.
- No buffer grows without bound.

### Errors come from the standard library

No error package: this module stopped depending on `github.com/juju/errors`, which Cams
still uses, and must not take it or another one back.

- **Context is added with `fmt.Errorf("...: %w", err)`**, so `errors.Is` and `errors.As`
  still reach the cause -- `fs.ErrNotExist` for a file `ServeTLS` cannot read, say.
- **A condition a caller may test is a constant of type `ConstError`**, declared with
  `const`, never a variable from `errors.New`: a variable can be reassigned by any package
  that imports this one. `ErrNoCertificatePath` in `utils/grpc.go` is the example.
- **Where the standard library has the sentinel, it is the one returned**:
  `errors.ErrUnsupported` for what is not written yet, as in `DialTLS`.
- **A message says what is wrong, and not the input that was wrong.** The caller has the
  path it passed; repeating it in the error only doubles it in a log line.
